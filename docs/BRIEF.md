# 프로젝트 브리프 — 따로 또 같이

**문서 버전:** v1.0
**작성일:** 2026-09-13
**상태:** Phase 1 + Phase 2 전체 구현·검증 완료, 프로덕션 운영 중 (https://twin-choice-ten.vercel.app)

> 이 문서는 프로젝트를 처음 접하는 사람이 5분 안에 "무엇을, 왜, 누구를 위해 만들었는가"를 파악하도록 돕는 요약 문서다. 요구사항의 전체 배경은 [PRD.md](PRD.md), 기술 구조의 상세는 [ARCHITECTURE.md](ARCHITECTURE.md), 기능 단위 상세는 [STORIES.md](STORIES.md)를 참고할 것.

---

## 1. 한 줄 요약

일란성 쌍둥이(및 형제자매) 자녀가 영상·과자·장난감 등을 고를 때 서로 눈치 보지 않도록, 블라인드로 각자 먼저 고르고 → 동시 공개 → 다르면 정해진 방법으로 조율하게 돕는 가족용 PWA. 부모는 그 기록을 통해 각 아이의 진짜 취향과 양보 패턴을 데이터로 파악한다.

## 2. 문제

- 쌍둥이·형제자매는 뭔가를 고를 때 자신의 진짜 선호보다 "상대가 좋아할지"를 먼저 신경 쓰며 반복적으로 양보하는 패턴을 보인다.
- 이 패턴이 굳어지면 부모가 각 아이의 진짜 취향을 파악하기 어려워지고, 억눌린 선호가 쌓여 장기적으로 자기 주관이 희석될 위험이 있다.
- 기존 가족용 의사결정 앱·육아 기록 앱은 "블라인드 선택 → 조율 → 성향 누적 분석"을 결합한 형태가 없다.

## 3. 해결 방향

1. **블라인드 선택**: 상대가 뭘 골랐는지 모르는 상태에서 각자 먼저 선택(그리드 탭 또는 사진 촬영).
2. **동시 공개 + 조율**: 양측 제출이 끝나면 자동 공개, 다르면 룰렛/번갈아하기/둘 다 하기/직접 정하기 중 하나로 다툼 없이 정리.
3. **부모 전용 관찰**: 양보 지수·주간 추이 그래프와, 최소 표본을 넘겼을 때만 버튼으로 보는 AI 관찰 요약 — 자녀 화면에는 절대 노출하지 않는다(단, `/history`는 명시적 예외 — [PRD.md](PRD.md) P0-5 구현 노트 참고).

## 4. 타겟 사용자

| 구분 | 설명 |
|---|---|
| **자녀 (선택 주체)** | 쌍둥이/형제자매. 로그인 계정 없이 가족 코드 + 프로필 선택 + PIN 4자리로 진입. 통계·양보 지수는 절대 못 봄(기록 화면 제외) |
| **부모 (관리자)** | 유일한 정식 로그인 주체(이메일). 자녀 프로필 생성·관리, 카테고리/항목 커스터마이징, 사진 아카이브, 대시보드·AI 관찰 요약 열람 |

## 5. 목표

- 아이가 상대 눈치를 보지 않고 먼저 자기 선호를 표현하는 비율을 높인다.
- 불일치 상황을 감정적 다툼 없이 조율하는 도구를 제공한다.
- 부모가 개입("이거 골라줘")이 아니라 관찰(사실 데이터 확인)만 하도록 역할을 제한한다.
- 운영 비용은 최소화: Supabase 무료 티어, AI 호출은 명시적 트리거로만(자동 실행 없음).

## 6. 범위

### 포함 (구현 완료)

- 부모 회원가입/로그인, 자녀 프로필 생성·PIN 로그인(5회 실패 시 1분 잠금), 자녀 얼굴 사진 아바타
- 블라인드 선택 → 동시 공개 → 조율(룰렛/번갈아하기/둘 다 하기/직접 정하기)
- 사진으로 고르기(AI 자유 라벨링 + 공개 시점 AI 비교, 저신뢰 시 수동 라벨 입력)
- 카테고리/항목 커스터마이징(부모 전용, soft delete)
- 사진 아카이브(부모, 라벨 재수정) + 자주 나온 사진 라벨 → 항목 승격 제안
- 기록(자녀/부모 공용) + "이번엔 누구 차례?" AI 제안(공정성 판단은 코드가 계산, AI는 문장만)
- 부모 대시보드(양보 지수, 주간 추이 그래프) + AI 관찰 요약(진단적 언어 금지 8원칙 적용)
- "왜 이게 좋아?" 음성으로 이유 남기기(Azure AI Speech STT, 음성 자체는 저장 안 함)
- Web Push 알림(라운드 생성/공개 시점)
- 파스텔 블록 카드 + 검은 선 아이콘 비주얼 리디자인
- Vercel 배포 + 자동 재배포, 해커톤 심사용 데모 진입점(`/demo`)

### 제외 (의도적 보류)

- 형제자매 3인 이상 UI(데이터 모델은 대비돼 있음)
- 데이터 CSV/PDF 내보내기
- 연인용/1인용 확장(제품 비전 탐색 후 명시적으로 폐기 — [PRD.md](PRD.md) 9절)
- 사업화(다중 테넌트, 결제) — 별도 트랙, 현재 범위 아님

## 7. 핵심 설계 결정 (요약)

| 결정 | 이유 |
|---|---|
| Supabase(Postgres+Auth+Storage+Realtime), 무료 티어 | 관계형 가족 데이터에 적합, RLS로 DB 레벨 접근 제어 |
| 자녀는 PIN으로 프로필 전환하되, 내부적으로는 synthetic 계정의 **실제 Supabase Auth 세션** 발급 | RLS가 "누구의 프로필인가"까지 DB 레벨에서 강제 가능 — 이 패턴이 자매 앱 `reading-buddy`로 이식됨 |
| 사진 AI는 Azure OpenAI (Claude API 아님) | 사용자가 Azure 비용을 직접 부담하기로 함 — 자동 호출 금지, 사진 촬영/공개 시점에만 호출 |
| 음성 인식은 Whisper 아닌 Azure AI Speech | 이 프로젝트의 Azure OpenAI 리소스 리전(Korea Central)에서 Whisper 모델 배포가 불가능해서(오디오 모델은 리전 지원이 좁음), reading-buddy가 이미 검증한 Azure AI Speech 리소스를 재사용 |
| AI 관찰 요약은 "진단"이 아니라 "관찰 요약"으로 프레이밍 | 이 앱의 데이터(장난감·과자 선택 몇 번)로 아이의 심리를 판정할 근거가 없음 — 8원칙을 시스템 프롬프트+출력 필터 이중으로 강제 |
| 사진으로 고르기는 "항목 매칭"이 아니라 "자유 라벨 + AI 직접 비교" | 원안(P0-3, 고정 항목 매칭)보다 실제 사용 패턴에 더 맞음 — 목록에 없는 물건도 자연스럽게 기록 가능 |
| 호스팅은 Vercel, 리전 `icn1`(서울) 고정 | Supabase가 서울 리전이라 리전 불일치 시 모든 서버 함수 호출에 추가 왕복이 생김 |

상세 배경은 [PRD.md](PRD.md), 기술 구조는 [ARCHITECTURE.md](ARCHITECTURE.md) 참고.

## 8. 현재 상태

- **Phase 1 (MVP)**: 인증/역할 분리, RLS, 블라인드 선택→공개→조율, 기록, 개인정보 최소 요건, 사진으로 고르기 — 전부 구현·실제 브라우저 검증 완료.
- **Phase 2 (6개 항목)**: 카테고리/항목 커스터마이징, 사진 아카이브, 부모 대시보드(양보 지수), AI 패턴 관찰 리포트, 푸시 알림, 자녀 프로필 사진 — 전부 구현·검증 완료.
- **번외 기능**: "왜 이게 좋아?" 음성 이유 남기기, 해커톤 심사용 데모 진입점(`/demo`), 기록 화면 확장 + 사진 라벨 승격 제안, 비주얼 리디자인(파스텔 블록 카드).
- **자매 앱 reading-buddy 개발 내역 역이식**: PIN 확인 버튼 UX, PIN 브루트포스 잠금, Vercel 리전 고정, 인증 이중 확인 제거, Vitest 테스트 인프라(25개) 도입.
- **AI 인프라 복구**: 원래 쓰던 Azure OpenAI 리소스가 삭제되어, reading-buddy의 기존 리소스(gpt-4o 배포 + Azure AI Speech)를 재사용하도록 전환. 그 과정에서 AI 호출 실패 시 핵심 흐름이 멈추던 버그(`/api/rounds/[id]/compare`의 무한 스피너 등)를 함께 수정.
- 프로덕션 URL: **https://twin-choice-ten.vercel.app**

세부 구현·검증 이력은 저장소 루트의 [CLAUDE.md](../CLAUDE.md)가 살아있는 소스로 관리한다.

## 9. 주요 리스크

- **Azure 리소스 삭제 재발 가능성** — 이번에 리소스가 통째로 사라지는 일을 실제로 겪었다. 현재는 reading-buddy와 리소스를 공유해서 완화됐지만, 그쪽 리소스가 사라지면 twin-choice도 같이 영향받는 새로운 결합도가 생겼다.
- **CHILD_AUTH_SECRET/서비스 키 분실 위험** — Vercel의 "Sensitive" 환경변수는 소유자도 CLI로 다시 못 읽는다. 이번에 실제로 `CHILD_AUTH_SECRET`을 분실해 재발급하며 일부 계정 PIN을 다시 받아야 했다. 생성 즉시 별도 백업 필요.
- **두 프로젝트(twin-choice/reading-buddy) 간 Azure 리소스 공유로 인한 트래픽 결합** — 한쪽 사용량이 늘면 다른 쪽 지연/쿼터에 영향 가능.
- **Supabase 무료 프로젝트의 비활성 자동 일시정지** — 방학 등 공백기 대비 정기 핑 장치 미구현.
